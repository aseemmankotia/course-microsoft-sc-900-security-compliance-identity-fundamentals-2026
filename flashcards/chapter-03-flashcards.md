## Chapter 3: Microsoft Entra: Access Management and Identity Governance — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Conditional Access: what are the three core components of a policy? | Signals (who, where, what device, what app, risk), Decisions (grant controls like require MFA/block), Enforcement (session controls like limited access). Exam tip: signals = inputs, decisions = outcome. |
| 2 | Sign-in risk vs User risk — what's the difference? | Sign-in risk = probability a specific authentication attempt isn't from the legitimate owner (e.g., anonymous IP, impossible travel). User risk = probability the identity itself is compromised (e.g., leaked credentials). Exam tip: leaked credentials = user risk, not sign-in risk. |
| 3 | PIM: Eligible vs Active assignment | Eligible = must activate the role (justification/MFA/approval) before it's usable, expires after set time. Active = role is already usable without activation. Exam tip: 'just-in-time access' = eligible assignment. |
| 4 | What license is required for Conditional Access? | Microsoft Entra ID P1 (included in P2). Exam tip: Conditional Access = P1 minimum. |
| 5 | What license is required for Identity Protection and PIM? | Microsoft Entra ID P2. Exam tip: P2 = risk-based features (Identity Protection) and privileged access (PIM). |
| 6 | What is entitlement management used for? | Bundling resources (apps, groups, SharePoint sites) into an 'access package' that users can self-service request, with approval workflows and automatic expiration. Exam tip: think external partner/guest onboarding scenarios. |
| 7 | What is an access review used for? | Periodic recertification of existing access (group membership, app access, role assignment) by a designated reviewer, with automatic removal if not confirmed. Exam tip: 'access reviews' = recurring, not initial request. |
| 8 | Microsoft Entra Verified ID is based on what standard? | W3C Verifiable Credentials — a decentralized identity standard. Users control and present their own portable digital credentials. Exam tip: 'decentralized identity' keyword = Verified ID. |
| 9 | Name two examples of Conditional Access signals. | User/group membership, network location (IP/named location), device platform/compliance state, client application, and real-time sign-in risk. Exam tip: risk level itself can be a signal AND trigger Identity Protection. |
| 10 | What is the difference between Conditional Access grant controls and session controls? | Grant controls decide whether access is allowed and under what condition (e.g., require MFA, compliant device). Session controls restrict what the user can do during the session (e.g., limited browser access, app enforced restrictions). Exam tip: grant = 'can they in', session = 'what can they do once in'. |
| 11 | What is Role-Based Access Control (RBAC) in Microsoft Entra ID? | Assigning built-in or custom directory roles (e.g., Global Administrator, User Administrator, Helpdesk Administrator) to grant only the permissions needed for a job function — principle of least privilege. Exam tip: never use Global Administrator for routine tasks. |
| 12 | Which Microsoft Entra feature enforces just-in-time, time-bound elevation of admin roles? | Privileged Identity Management (PIM). Exam tip: PIM = time-bound + activation + approval/MFA for privileged roles, distinct from standard RBAC assignment. |
