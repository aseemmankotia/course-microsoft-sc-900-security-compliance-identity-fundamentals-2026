## Chapter 2: Microsoft Entra ID: Identities and Authentication — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | SSPR default 'Number of methods required to reset' setting? | 2. Admins can lower it to 1, but the default enforces two authentication methods for a password reset. Exam tip: SSPR security relies on multiple verification methods. |
| 2 | Name the three Microsoft-recommended passwordless authentication methods. | Windows Hello for Business, FIDO2 security keys, Microsoft Authenticator (phone sign-in). Exam tip: all three eliminate the password entirely, unlike SMS/voice MFA. |
| 3 | List the five Microsoft Entra ID identity types tested on SC-900. | User, Group, Device, Service Principal, Managed Identity. Exam tip: managed identity = auto-managed credentials for Azure resources; service principal = app identity with manually managed credentials. |
| 4 | System-assigned vs user-assigned managed identity — key difference? | System-assigned: tied 1:1 to a single resource, deleted when resource is deleted. User-assigned: standalone resource that can be shared across multiple Azure resources. Exam tip: exam tests which type persists after resource deletion (user-assigned). |
| 5 | Microsoft Entra B2B vs Entra External ID (B2C) — when to use each? | B2B: invite external partner/business users as guests to collaborate on internal resources. External ID (B2C): consumer-facing apps where customers sign up/sign in, including via social IdPs (Google, Facebook). Exam tip: 'partner access' = B2B, 'customer sign-up app' = External ID. |
| 6 | List common MFA verification methods in Microsoft Entra ID. | Microsoft Authenticator (push notification or passwordless), SMS, voice call, OATH hardware token, OATH software token (authenticator app OTP). Exam tip: distinguish MFA methods (still use password) from passwordless methods (no password at all). |
| 7 | What are the three federation/sync options in Microsoft Entra Connect? | Password Hash Synchronization (PHS), Pass-through Authentication (PTA), Federation with AD FS. Exam tip: PHS is simplest/most resilient; AD FS federation requires on-prem infrastructure and adds complexity. |
| 8 | Why is FIDO2 considered 'phishing-resistant'? | It uses public/private key cryptography bound to the specific website/service origin, so credentials cannot be reused or replayed on a fake site. Exam tip: FIDO2 keys are hardware-based passwordless authentication. |
| 9 | Does the free tier of Microsoft Entra ID support SSPR? | Free tier supports SSPR only for cloud-only accounts to unlock their account (limited); full SSPR with writeback to on-prem AD requires Microsoft Entra ID P1 or P2. Exam tip: 'password writeback' = premium feature. |
| 10 | Service principal vs Managed Identity — who manages the credentials? | Service principal: developer/admin manually creates and rotates secrets/certificates. Managed identity: Azure automatically creates and rotates credentials, never exposed to the developer. Exam tip: 'no credentials in code' scenario = managed identity. |
| 11 | Windows Hello for Business — what is it bound to? | A specific registered/joined device; uses biometrics (face/fingerprint) or a PIN backed by a TPM-protected key pair. Exam tip: not portable across devices — must be set up per device. |
| 12 | Microsoft Entra External ID (formerly Azure AD B2C) — supported identity providers? | Local accounts plus social/federated IdPs such as Google, Facebook, and Microsoft account, as well as enterprise IdPs via SAML/OIDC. Exam tip: this is the go-to answer for 'consumer app with social login' scenarios. |
